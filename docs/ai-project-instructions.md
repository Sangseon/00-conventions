# AI Project Instructions Convention

AI 개발 도구가 Repository에서 지속적으로 참조하는 프로젝트 지침 파일의 작성 및 관리 기준을 정의한다.

이 Convention은 Codex의 `AGENTS.md`, Claude Code의 `CLAUDE.md` 및 도구별로 지원하는 지침 체계를 대상으로 한다. 특정 파일의 존재를 모든 프로젝트에 강제하지 않으며, 사용하는 도구와 프로젝트의 실제 필요에 따라 적용한다.

## 1. Purpose

프로젝트 지침은 작업을 반복할 때마다 재설명할 필요가 없는 규칙과 제약을 전달하기 위한 문서다.

- 프로젝트의 목적, 구조, 기술 선택 및 작업 기준을 일관되게 유지한다.
- AI 도구별 지침 인식 방식의 차이를 고려한다.
- 중복·충돌·오래된 지침으로 인한 잘못된 변경을 줄인다.
- 현재 작업에 필요한 정보만 참조하여 불필요한 컨텍스트를 최소화한다.
- 사용자의 승인 없이 수행해서는 안 되는 작업을 명확히 구분한다.

특정 작업의 구현 요구사항과 완료 기준은 별도의 `AI Task Prompt Convention`에 따라 작성한다.

---

## 2. Common Principles

### 2.1. 지속적인 규칙만 기록

여러 작업에 걸쳐 유지해야 할 기준을 중심으로 작성한다. 일회성 Step 요구사항, 임시 오류 분석, 수행한 작업의 상세 이력은 프로젝트 계획·작업 기록 또는 개별 프롬프트에서 관리한다.

### 2.2. 구체적이고 검증 가능한 지침

'코드를 깔끔하게 작성한다'보다 '기존 TypeScript strict 설정을 유지한다'처럼 행동과 검증 기준이 드러나도록 작성한다.

### 2.3. 현재 Repository 기준

실제 파일, 실행 명령 및 프로젝트 정책을 기준으로 작성한다. 확인하지 못한 정보는 사실로 단정하지 않는다. 파일명이나 스크립트를 변경한 경우 관련 지침도 함께 갱신한다.

### 2.4. 간결성과 역할 분리

모든 문서를 복제하지 않고, 반복적으로 필요한 핵심 규칙과 관련 문서의 위치를 안내한다. 단순 수정에도 모든 문서를 일괄 읽도록 강제하지 않고 작업에 관련된 문서를 선택적으로 참조하도록 한다.

### 2.5. 강제력의 한계

Markdown 지침은 AI의 행동을 유도하는 문맥이지 파일 변경·명령 실행을 기술적으로 차단하는 보안 장치는 아니다. 중요한 제약은 도구 권한, 승인 설정, 보호 규칙, CI 또는 Hook 등으로 별도 강제하는 방안을 검토한다.

## 3. Instruction File Roles

| File or Mechanism                    | Primary Role                                                    |
| ------------------------------------ | --------------------------------------------------------------- |
| `AGENTS.md`                          | Codex 등 지원 도구에서 사용하는 Repository·디렉터리별 지속 지침 |
| `CLAUDE.md`                          | Claude Code에서 사용하는 프로젝트 지속 지침 및 외부 지침 참조   |
| `.claude/rules/`                     | Claude Code의 세부 주제·경로별 규칙(필요한 경우)                |
| `README.md`                          | 사람을 위한 프로젝트 소개와 사용 방법                           |
| `docs/Concept.md`, `docs/PLAN.md` 등 | 설계 배경, 정책, 진행 계획 및 단계별 요구사항                   |
| 개별 작업 프롬프트                   | 지금 수행할 작업의 목표, 범위, 검증 및 산출물                   |

위 파일명과 디렉터리는 예시다. 기존 Repository의 문서명과 대소문자를 임의로 변경하지 않는다.

지침은 프로젝트 문서를 대체하지 않으며, 프로젝트 문서 역시 도구가 자동으로 인식하는 지침 파일과 동일하지 않다.

## 4. Tool-Specific Behavior

### 4.1. Codex

Codex는 지원 환경에서 `AGENTS.md`를 Repository 작업 지침으로 사용한다. 상위 디렉터리, 하위 디렉터리 및 사용자 설정에 따른 검색·적용 범위는 사용하는 Codex 버전과 실행 환경의 공식 문서를 기준으로 확인한다.

- Repository 공통 지침은 일반적으로 루트 `AGENTS.md`에 둔다.
- 특정 디렉터리에만 해당하는 규칙은 필요할 때 더 좁은 범위로 분리한다.
- 지침 적용 범위를 실제 실행 위치와 도구 설정을 통해 확인한다.

### 4.2. Claude Code

Claude Code는 `CLAUDE.md`를 프로젝트 지침으로 사용하며, 지원 버전에서는 `AGENTS.md`도 읽을 수 있다.

**`AGENTS.md`와 `CLAUDE.md`가 함께 있는 경우 어느 파일을 읽는지는 Claude Code의 지원 버전과 설정에 따라 달라질 수 있다.** 두 파일을 항상 자동 병합한다고 가정하지 않는다.

`CLAUDE.md`는 `@파일경로` 형식의 import를 지원한다. 공통 지침을 `AGENTS.md`로 관리하는 프로젝트라면, 사용 중인 Claude Code에서 import가 정상 적용되는지 확인한 뒤 다음 방식을 선택할 수 있다.

```md
# Claude Code Instructions

@AGENTS.md
```

단, 이는 가능한 **공유 방식의 예시**이며 모든 프로젝트에서 `AGENTS.md`를 유일한 기준 파일로 사용할 것을 강제하지 않는다. Claude Code 전용 규칙이 필요하면 `CLAUDE.md` 또는 지원되는 별도 규칙 파일에서 관리한다.

### 4.3. 도구 변경에 대한 대응

AI 개발 도구의 지침 탐색 경로, 우선순위, import 및 지원 기능은 변경될 수 있다. 특정 버전에서만 동작하는 기능은 확인한 근거와 적용 조건을 남기고 필요할 때 재검증한다.

## 5. Recommended Instruction Content

프로젝트 성격에 따라 다음 항목 중 필요한 내용만 포함한다.

| Component               | Description                                                       |
| ----------------------- | ----------------------------------------------------------------- |
| Project Overview        | 프로젝트 목적 및 학습·운영 성격                                   |
| Architecture            | 주요 구성 요소와 책임 경계                                        |
| Development Environment | 언어·런타임·프레임워크와 주요 버전 제약                           |
| Coding Conventions      | 기존 코드 스타일과 기술 선택을 유지하는 기준                      |
| Build and Test          | 실제 존재하는 실행·검증 명령과 적용 범위                          |
| Change Constraints      | 변경 금지 대상, 호환성 및 단계별 작업 경계                        |
| Safety and Approval     | Git Commit·Push, 배포, 데이터 삭제, 외부 서비스 변경 등 승인 기준 |
| Documentation           | 어떤 변경 시 어떤 문서를 갱신하는지                               |
| Reporting               | 검증 사실, 미실행 항목, 남은 문제의 보고 방식                     |

모든 항목을 독립된 Section으로 만들 필요는 없다. 비슷한 지침을 합치고, 상세 실행 절차는 필요한 경우 관련 문서로 분리한다.

## 6. Shared and Tool-Specific Instructions

하나의 Repository에서 여러 AI 도구를 사용할 때는 공통 규칙의 중복 관리를 최소화한다.

1. 공통 규칙을 관리할 기준 위치를 정한다.
2. 도구별 인식 및 import 기능을 확인한다.
3. 도구 전용 설정이나 명령은 해당 도구의 지침에만 둔다.
4. 동일한 내용이 중복되면 기준 문서를 명확히 하고 충돌 여부를 확인한다.
5. 지침 파일이 하나뿐인 프로젝트에서도 해당 도구가 실제로 이를 읽는지 검증한다.

공통 기준 파일은 프로젝트 상황에 따라 선택한다. 다른 도구가 어떤 파일을 자동으로 읽는지 추정하여 구조를 정하지 않는다.

---

## 7. Scope and Precedence

지침 적용 범위는 Repository 전체, 특정 하위 디렉터리, 특정 작업으로 구분한다.

- Repository 전체에 적용되는 규칙은 공통 지침에 둔다.
- 특정 언어·모듈에만 적용되는 규칙은 지원되는 경로별 지침으로 분리할 수 있다.
- 특정 Step의 목표와 제외 범위는 개별 작업 프롬프트에 둔다.
- 상위 지침, 도구 설정 및 사용자 요청의 우선순위는 해당 AI 도구의 실제 규칙을 따른다.

충돌이 발견되면 우선순위가 불명확한 내용을 임의로 선택하지 말고 충돌 항목과 영향 범위를 보고하도록 한다.

지속 지침에 단일 작업의 임시 예외를 추가할 때에는 적용 범위와 제거 시점을 명확히 하거나 개별 프롬프트에서 관리한다.

---

## 8. Validation and Review

새 지침을 도입하거나 변경하면 다음을 확인한다.

- 파일이 해당 AI 도구에서 실제로 인식되는지
- import나 참조 경로가 정상적으로 해석되는지
- 기존 지침 및 작업 프롬프트와 충돌하지 않는지
- 안내한 파일과 빌드·테스트 명령이 실제로 존재하는지
- 설정된 승인 범위를 넘어 Git·배포·외부 시스템 변경을 요구하지 않는지
- 관련 없는 작업에 불필요한 지침을 과도하게 적용하지 않는지

실제 확인하지 않은 사항은 검증 완료로 기록하지 않는다. 지침 파일만으로 금지된 명령이 기술적으로 차단된다고 간주하지 않는다.

## 9. Examples

아래 예시는 프로젝트에 맞게 조정하기 위한 참고이며 고정 템플릿이 아니다.

### 9.1. Codex 중심 프로젝트

```text
my-project/
├─ AGENTS.md
├─ README.md
└─ docs/
   ├─ Concept.md
   └─ PLAN.md
```

`AGENTS.md`에는 기존 코드 정책, 실행·테스트 방법, 관련 문서의 역할, 승인 필요한 작업을 작성한다. 특정 Step의 기능 요구사항은 개별 프롬프트에서 관리한다.

### 9.2. Codex와 Claude Code를 함께 사용하는 프로젝트

```text
my-project/
├─ AGENTS.md
├─ CLAUDE.md
├─ README.md
└─ docs/
   └─ PLAN.md
```

`AGENTS.md`를 공통 지침으로 선택한 경우 `CLAUDE.md`에서 import할 수 있다. 다만 두 도구에서 실제 로딩 여부를 확인하고, 필요하다면 도구 전용 규칙을 별도로 기록한다.

### 9.3. 지속 규칙과 작업 요청의 구분

| Instruction                                        | Recommended Owner                                       |
| -------------------------------------------------- | ------------------------------------------------------- |
| 기존 TypeScript strict 설정 유지                   | 프로젝트 지침                                           |
| Commit·Push는 사용자 승인 후 수행                  | 프로젝트 지침 및 도구 권한 설정                         |
| 이번 Step에서는 카메라·마이크 로컬 미리보기만 구현 | 작업 프롬프트                                           |
| 다음 Step에서 SFU 송신 구현 예정                   | 프로젝트 계획 문서                                      |
| Step 종료 후 실제 테스트 결과 보고                 | 프로젝트 지침의 일반 원칙 + 작업 프롬프트의 구체적 기준 |

## 10. Maintenance

- 프로젝트의 설계·실행 환경·도구 버전이 변경되면 관련 지침을 검토한다.
- 여러 작업에서 반복되는 문제를 해결하는 데 유용한 규칙만 지속 지침에 추가한다.
- 현재 코드와 불일치하거나 적용 효과가 없는 규칙은 수정하거나 제거한다.
- 파일 참조와 import의 중복·순환·충돌 여부를 확인한다.
- 특정 도구의 최신 동작은 공식 문서를 통해 재확인한다.
- 기존 Repository의 지침 구조를 일괄적으로 변경할 필요는 없다.
- Convention의 상태와 `Last Updated`는 `00-conventions/README.md`에서 관리한다.

이 문서는 Draft 단계의 작성 기준이며, 실제 프로젝트 적용과 검증을 거쳐 개선한다.
